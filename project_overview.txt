\chapter*{Abstract}

Modern computer systems rely heavily on efficient storage access mechanisms.
As applications become increasingly data-intensive, storage I/O has emerged
as one of the major performance bottlenecks in operating systems.

Traditional disk scheduling algorithms such as FCFS, SSTF, Deadline,
and CFQ use fixed heuristics that are unable to adapt dynamically
to changing workload patterns. These schedulers may perform well
under certain conditions but fail to optimize performance
for mixed or unpredictable workloads.

This project introduces an intelligent I/O scheduling framework
that combines Machine Learning techniques with Operating System
disk scheduling concepts. The proposed system predicts the service
time of disk requests using a neural network model and dynamically
reorders requests based on predicted latency.

The system consists of several major components including:

\begin{itemize}

\item Data Collection Module
\item Feature Extraction Engine
\item Neural Network Prediction Model
\item Intelligent Scheduler
\item Starvation Prevention Mechanism
\item Performance Evaluation Framework

\end{itemize}

The proposed ML-based scheduler follows a modified
Shortest-Job-First strategy that minimizes average waiting time
while ensuring fairness using anti-starvation techniques.

Experimental results demonstrate significant improvements in:

\begin{itemize}

\item Throughput
\item Average Latency
\item Tail Latency
\item Resource Utilization

\end{itemize}

The project demonstrates how Artificial Intelligence can be
integrated with Operating System components to build adaptive
and efficient storage systems.

\vspace{1cm}

\textbf{Keywords:}

Operating System,
Disk Scheduling,
Machine Learning,
Neural Networks,
Storage Systems,
I/O Optimization,
Latency Prediction

\section{Background}

Storage systems are fundamental components of modern computer systems.
Every application relies on efficient storage access mechanisms
for reading and writing data.

Whenever a user opens a file, launches an application,
downloads media, runs a database query,
or performs machine learning computations,
the operating system generates Input/Output (I/O) requests.

These requests are handled by storage devices such as:

\begin{itemize}

\item Hard Disk Drives (HDDs)
\item Solid State Drives (SSDs)
\item NVMe Devices
\item Distributed Storage Systems

\end{itemize}

As the number of applications increases,
multiple processes compete simultaneously for disk access.

Efficient scheduling of these requests becomes extremely important.

The operating system uses a component called the
\textbf{I/O Scheduler} to determine the order
in which requests are serviced.

% =========================================================
% SECTION 1.2
% =========================================================

\section{Problem Statement}

Traditional scheduling algorithms use fixed heuristics.

Examples include:

\begin{itemize}

\item FCFS (First Come First Serve)
\item SSTF (Shortest Seek Time First)
\item SCAN
\item C-SCAN
\item Deadline Scheduler
\item CFQ (Completely Fair Queuing)

\end{itemize}

Although these algorithms are efficient in specific scenarios,
they cannot dynamically adapt to changing workloads.

For example:

\begin{itemize}

\item Database workloads require low latency random reads
\item Backup workloads generate sequential writes
\item Multimedia systems require predictable throughput
\item Cloud systems demand fairness among tenants

\end{itemize}

A static scheduler cannot intelligently balance all these
requirements simultaneously.

\section{Existing System}

Traditional operating systems use predefined scheduling policies.

Some common schedulers are discussed below.

% =========================================================
% SUBSECTION
% =========================================================

\subsection{First Come First Serve (FCFS)}

FCFS services requests in the exact order in which they arrive.

\subsubsection{Advantages}

\begin{itemize}

\item Very simple implementation
\item Fair scheduling order
\item Minimal overhead

\end{itemize}

\subsubsection{Disadvantages}

\begin{itemize}

\item Poor seek optimization
\item High average waiting time
\item Low throughput

\end{itemize}

% =========================================================
% SUBSECTION
% =========================================================

\subsection{Shortest Seek Time First (SSTF)}

SSTF selects the request closest to the current disk head position.

\subsubsection{Advantages}

\begin{itemize}

\item Reduces seek time
\item Improves throughput

\end{itemize}

\subsubsection{Disadvantages}

\begin{itemize}

\item Can cause starvation
\item Unfair to distant requests

\end{itemize}

% =========================================================
% SUBSECTION
% =========================================================

\subsection{SCAN Scheduler}

SCAN moves the disk head in one direction while servicing requests.

\subsubsection{Advantages}

\begin{itemize}

\item Better fairness
\item Reduced starvation

\end{itemize}

\subsubsection{Disadvantages}

\begin{itemize}

\item Increased waiting time for some requests

\end{itemize}

% =========================================================
% SUBSECTION
% =========================================================

\subsection{Deadline Scheduler}

Deadline scheduling prevents starvation using expiration timers.

\subsubsection{Advantages}

\begin{itemize}

\item Prevents starvation
\item Better responsiveness

\end{itemize}

\subsubsection{Disadvantages}

\begin{itemize}

\item Static heuristics
\item Limited adaptability

\end{itemize}

% =========================================================
% SUBSECTION
% =========================================================

\subsection{CFQ Scheduler}

Completely Fair Queuing allocates equal time slices among processes.

\subsubsection{Advantages}

\begin{itemize}

\item Fair scheduling
\item Suitable for multitasking

\end{itemize}

\subsubsection{Disadvantages}

\begin{itemize}

\item Complex implementation
\item Lower performance under mixed workloads

\end{itemize}

\section{Proposed System}

The proposed system introduces an intelligent Machine Learning based
I/O scheduler capable of predicting request service times.

Instead of relying on static heuristics,
the scheduler dynamically learns workload behavior.

The system architecture includes:

\begin{enumerate}

\item Trace Collection Module
\item Feature Extraction Module
\item ML Prediction Engine
\item Intelligent Scheduling Engine
\item Anti-Starvation Mechanism
\item Benchmarking Framework

\end{enumerate}

The scheduler uses a modified Shortest-Job-First approach.

The Machine Learning model predicts the expected latency
for each request.

Requests with smaller predicted latency are serviced first,
thereby minimizing average waiting time.

To prevent starvation,
an aging mechanism periodically boosts the priority
of long-waiting requests.

\section{Introduction to Disk Scheduling}

Disk scheduling is one of the most important responsibilities
of an operating system.

Whenever multiple processes generate Input/Output requests,
the operating system must decide the order
in which requests should be serviced.

This process is known as \textbf{Disk Scheduling}.

Efficient disk scheduling improves:

\begin{itemize}

\item System throughput
\item Average response time
\item CPU utilization
\item Resource efficiency
\item Overall system performance

\end{itemize}

Poor scheduling increases:

\begin{itemize}

\item Waiting time
\item Seek overhead
\item Queue congestion
\item Disk latency

\end{itemize}

\section{Disk Access Time}

Disk access time refers to the total time required
to service an I/O request.

The total access time includes:

\begin{enumerate}

\item Seek Time
\item Rotational Latency
\item Transfer Time

\end{enumerate}

The formula for total access time is:

\[
Access\ Time =
Seek\ Time +
Rotational\ Latency +
Transfer\ Time
\]

% =========================================================
% SECTION 2.5
% SEEK TIME
% =========================================================

\section{Seek Time}

Seek time is the time required to move
the disk head from one track to another.

Seek time depends on:

\begin{itemize}

\item Distance between tracks
\item Speed of actuator arm
\item Disk mechanics

\end{itemize}

The seek time equation is:

\[
T_s = m \times n + s
\]

Where:

\begin{itemize}

\item $T_s$ = Seek Time
\item $m$ = Seek constant
\item $n$ = Number of tracks moved
\item $s$ = Startup overhead

\end{itemize}

Large seek distances increase access time significantly.

% =========================================================
% SECTION 2.6
% ROTATIONAL LATENCY
% =========================================================

\section{Rotational Latency}

Rotational latency is the waiting time
for the desired sector to rotate
under the read/write head.

Average rotational latency is:

\[
Rotational\ Latency =
\frac{1}{2} \times Rotation\ Time
\]

If disk speed is represented in RPM:

\[
Rotation\ Time =
\frac{60}{RPM}
\]

Example:

For a 7200 RPM disk:

\[
Rotation\ Time =
\frac{60}{7200}
= 0.0083\ seconds
\]

Average rotational latency:

\[
= 4.16\ ms
\]

% =========================================================
% SECTION 2.7
% TRANSFER TIME
% =========================================================

\section{Transfer Time}

Transfer time refers to the time required
to actually transfer data between disk and memory.

The formula is:

\[
Transfer\ Time =
\frac{Data\ Size}{Transfer\ Rate}
\]

Large files require more transfer time.

\section{Traditional Disk Scheduling Algorithms}

Several traditional scheduling algorithms
have been proposed in Operating Systems.

% =========================================================
% SUBSECTION
% =========================================================

\subsection{First Come First Serve (FCFS)}

FCFS services requests in arrival order.

Example Queue:

\[
98,\ 183,\ 37,\ 122,\ 14,\ 124
\]

Advantages:

\begin{itemize}

\item Simple implementation
\item Fair ordering

\end{itemize}

Disadvantages:

\begin{itemize}

\item Poor performance
\item Large seek overhead

\end{itemize}

% =========================================================
% SUBSECTION
% =========================================================

\subsection{Shortest Seek Time First (SSTF)}

SSTF selects the request nearest
to the current head position.

Advantages:

\begin{itemize}

\item Reduced seek movement
\item Improved throughput

\end{itemize}

Disadvantages:

\begin{itemize}

\item Starvation possible
\item Unfair scheduling

\end{itemize}

% =========================================================
% SUBSECTION
% =========================================================

\subsection{SCAN Algorithm}

SCAN moves the disk head in one direction
while servicing requests.

It behaves similarly to an elevator.

Advantages:

\begin{itemize}

\item Better fairness
\item Reduced starvation

\end{itemize}

Disadvantages:

\begin{itemize}

\item Some requests may wait longer

\end{itemize}

% =========================================================
% SUBSECTION
% =========================================================

\subsection{C-SCAN Algorithm}

Circular SCAN services requests in one direction only.

After reaching the end,
the head returns to the beginning.

Advantages:

\begin{itemize}

\item Uniform waiting time
\item Fair scheduling

\end{itemize}

Disadvantages:

\begin{itemize}

\item Additional head movement

\end{itemize}

% =========================================================
% SUBSECTION
% =========================================================

\subsection{LOOK Algorithm}

LOOK is an optimized version of SCAN.

The head moves only as far as the final request.

Advantages:

\begin{itemize}

\item Reduced unnecessary movement
\item Better efficiency

\end{itemize}

% =========================================================
% SUBSECTION
% =========================================================

\subsection{C-LOOK Algorithm}

C-LOOK is an optimized version of C-SCAN.

The head jumps directly to the first request
instead of moving to the physical disk end.

Advantages:

\begin{itemize}

\item Reduced seek overhead
\item Improved performance

\end{itemize}

The scheduler follows a modified

Requests with smaller predicted latency
are serviced first.

The scheduler stores requests
inside a priority queue.

Priority is determined by:

\[
Priority \propto Predicted\ Latency
\]

Lower predicted latency
means higher scheduling priority.

\item Predict latency
\item Insert into priority queue

\item Record actual completion time

\end{enumerate}

\section{Anti-Starvation Module}

Pure Shortest-Job-First scheduling
may cause starvation.

Long requests may never get serviced
if shorter requests continuously arrive.

To solve this problem,
an anti-starvation mechanism is introduced.

% =========================================================
% SUBSECTION
% =========================================================

\subsection{Aging Mechanism}

The scheduler periodically increases
the priority of waiting requests.

If request waiting time exceeds a threshold:

\[
Waiting\ Time > Threshold
\]

then:

\[
Priority = Highest
\]

This guarantees fairness.

% =========================================================
% SUBSECTION
% =========================================================

\subsection{Benefits}

\begin{itemize}

\item Prevents starvation
\item Improves fairness
\item Maintains throughput
\item Ensures bounded waiting time

\end{itemize}

from datetime import datetime

class TraceCollector:

    def __init__(self,
                 device="/dev/sda",

        self.device = device
        self.duration = duration

    def start_collection(self):

        command = (
            f"blktrace -d {self.device} "

        process = subprocess.Popen(
            command.split()
        )

        print("Trace collection started")

        return process

    def parse_traces(self):

        command = (

        )

        subprocess.run(command.split())

        print("Trace parsing completed")

\section{Priority Queue Implementation}

A min-heap priority queue is used
for efficient scheduling.

% =========================================================
% PRIORITY QUEUE CODE
% =========================================================

\begin{lstlisting}[language=Python,
caption={Priority Queue Scheduler}]

import heapq

class MLScheduler:

    def __init__(self):

        self.queue = []

    def enqueue(
        self,
        request,
        predicted_latency
    ):

        heapq.heappush(

            self.queue,

            (
                predicted_latency,
                request
            )

        )

    def dequeue(self):

        return heapq.heappop(
            self.queue
        )

\end{lstlisting}

\section{HDD Simulator Model}

The HDD simulator models
real disk behavior mathematically.

% =========================================================
% EQUATION
% =========================================================

\[
Total\ Access\ Time =
Seek\ Time +
Rotational\ Latency +
Transfer\ Time
\]

% =========================================================
% SUBSECTION
% =========================================================

\subsection{Seek Time Calculation}

\[
Seek\ Time =
Distance \times Seek\ Constant
\]

Example:

\[
Seek\ Time =
20 \times 0.1 = 2ms
\]

% =========================================================
% SUBSECTION
% =========================================================

\subsection{Rotational Latency}

\[
Rotational\ Latency =
\frac{60}{2 \times RPM}
\]

For a 7200 RPM disk:

\[
= 4.16ms
\]

% =========================================================
% SUBSECTION
% =========================================================

\subsection{Transfer Time}

\[
Transfer\ Time =
\frac{Data\ Size}{Transfer\ Rate}
\]

% =========================================================
% SECTION 6.4
% HDD SIMULATOR CODE
% =========================================================

\section{HDD Simulator Code}

\begin{lstlisting}[language=Python,
caption={HDD Simulator Implementation}]

class HDDSimulator:

    def __init__(self):

        self.seek_constant = 0.1
        self.rotation_latency = 4.16
        self.transfer_rate = 150

    def compute_service_time(
        self,
        request
    ):

        seek_time = (
            abs(
                request["sector"]
                -
                request["current_sector"]
            )
            *
            self.seek_constant
        )

        transfer_time = (
            request["size"]
            /
            self.transfer_rate
        )

        total_time = (
            seek_time
            +
            self.rotation_latency
            +
            transfer_time
        )

        return total_time

\end{lstlisting}

\section{FIFO Scheduler Implementation}

\begin{lstlisting}[language=Python,
caption={FIFO Scheduler}]

class FIFOScheduler:

    def __init__(self):

        self.queue = []

    def enqueue(self, request):

        self.queue.append(request)

    def dequeue(self):

        if len(self.queue) == 0:

            return None

        return self.queue.pop(0)

\end{lstlisting}

\begin{lstlisting}[language=Python,
caption={SJF Scheduler}]

class SJFScheduler:

    def __init__(self):

        self.queue = []

    def enqueue(
        self,
        request
    ):

        self.queue.append(request)

        self.queue.sort(
            key=lambda x: x["size"]
        )

    def dequeue(self):

        return self.queue.pop(0)

\end{lstlisting}

\chapter{Glossary}

% =========================================================
% GLOSSARY ITEMS
% =========================================================

\section*{Latency}

The time required
to complete an I/O request.

\vspace{0.5cm}

\section*{Throughput}

The number of requests processed
per second.

\vspace{0.5cm}

\section*{Queue Depth}

The number of pending requests
inside the scheduler queue.

\vspace{0.5cm}

\section*{Seek Time}

The time required
for the disk head
to move between tracks.

\vspace{0.5cm}

\section*{Rotational Latency}

The waiting time
for the desired sector
to rotate under the read/write head.

\vspace{0.5cm}

\section*{Machine Learning}

A branch of Artificial Intelligence
that enables systems
to learn patterns from data.
